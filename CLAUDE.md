# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **Quarto book** — an open, freely-editable graduate statistics textbook for the social and behavioral sciences (working title in `_quarto.yml`: "Statistics by Us for You"). The "source" is a set of `.qmd` (Quarto Markdown) chapter files that interleave English prose with executable **R** code chunks. There is no application to run and no test suite; the deliverable is the rendered HTML book in `_book/`.

## Build & preview

```sh
quarto preview      # live-reloading local server; use this while editing
quarto render       # full build of the whole book into _book/
quarto render 02-distributions.qmd   # render a single chapter (faster feedback)
```

Rendering **executes every R code chunk**. A chapter can therefore break the build through a runtime R error (missing package, bad object) — not just a Markdown mistake. When a render fails, read the R error in Quarto's output, not just the Markdown.

Requires: `quarto` (1.6.x), `R` with `knitr`, and the packages a chapter loads (currently `ggplot2`, `plotly`; add more as chapters grow). Install missing R packages with `install.packages("<pkg>")` in R before rendering.

## Structure

- **Chapter order and book metadata live in `_quarto.yml`** (`book.chapters`), NOT in filename order. A new `.qmd` file is invisible to the book until it is added to that list. Chapters are grouped into `part:` sections ("The Basics", "Making Inferences with Data", "Checking Our Data", "Using Models").
- Front matter: `index.qmd` (welcome/license), `preface.qmd`, `author.qmd`, `intro.qmd`. Numbered files `02-`…`17-` are the body chapters; `references.qmd` closes the book.
- `_book/` is generated output — do not hand-edit; it is regenerated by `quarto render`.
- `img/` holds figures (e.g. the cover `img/MRES2wbg.png`).

## Bibliography

- Two BibTeX files, both referenced from `_quarto.yml`: `statbook.bib` (hand-maintained sources) and `packages.bib` (**auto-generated** — do not hand-edit).
- `packages.bib` is regenerated on render by the `knitr::write_bib(...)` chunk in `index.qmd`. To add a package citation, load the package in a chapter and let that chunk regenerate the entry.
- Cite in prose with Quarto/pandoc syntax, e.g. `@McKnight2007`; `link-citations` and `apalike` style are set in `_quarto.yml`.

## Conventions & current state

- **Work in progress.** Many chapters are intentionally stubs — `17-basicANOVA.qmd` is empty, and several files contain only headers or literal `foo`/`bar`/`baz` placeholders inside `::: {.callout-important}` blocks. This is expected; do not treat placeholder content as a bug to "fix" unless asked to write that section.
- **Voice matters.** The prose is informal, personal, warm, and *supportive* — an encouraging teacher, not a stand-up act. First-person asides marked `(PEM)` are welcome. **Avoid sarcasm, innuendo, and forced cleverness, and avoid AI-writing tics** (em-dash pile-ups, rule-of-three flourishes, breathless hype, rhetorical-question spam, "it's not just X, it's Y"). Write plainly and clearly, the way McKnight and Kashdan actually write. When in doubt, cut the joke and keep the point.
- **POMP is the house standardization.** Percent Of Maximum Possible — `100 * (x - min) / (max - min)` — puts differently-scaled measures on a common 0–100 scale. Introduced in `06-zdistribution.qmd`; prefer it when comparing across measures.
- R chunks are teaching artifacts: keep them short, self-contained, and heavily commented so a student can read them top to bottom.
- **The running code is tidyverse throughout.** Each chapter opens its first chunk with `library(tidyverse)` (plus `library(broom)` where models appear) and `source("_common.R")`. Use `tibble`/`dplyr` over `data.frame`/`$`-indexing, `purrr::map_*` over `sapply`/`replicate`, `readr::read_csv` over `read.csv`, and `ggplot2` for every figure; `plotly` is used for interactive 3D (the learning-helix in `intro.qmd`). The *statistical engines* stay base R — `lm`, `aov`, `glm`, `factanal`, `prcomp` — as do from-scratch teaching derivations; `broom` (`tidy`/`glance`/`augment`) turns their output into printable tables.
- **Numbers print to two decimal places**, via `round2()` from `_common.R`; models go through `tidy2()`. P-values are the exception — `fmt_p()` gives three decimals with a `< .001` floor, because a p-value shown as `0.00` misteaches. `22-tables.qmd` deliberately overrides this, since that chapter is about choosing digits on purpose. `_common.R` is reprinted in full in `required-packages.qmd`, so add any new helper there too.
- Sequential algorithms (EM in `29-latentclass.qmd`, JMLE in `18-rasch.qmd`) keep their outer `for` loop — each sweep depends on the last — with a comment saying so; only the genuinely independent inner sweeps use `map_*`.
- **Every executable chunk is wrapped in a four-language `::: {.panel-tabset}`**, headers in this order: `### R` / `### SPSS` / `### Julia` / `### Python`. Only the R tab is a live `{r}` chunk; SPSS uses a bare fence, Julia ```julia, Python ```python (all three are highlight-only, so the build needs no SPSS/Julia/Python). When a language genuinely lacks the procedure, its tab says so plainly and names the tool that does it — never invent syntax that would not run. The `three-languages.qmd` appendix keeps its filename despite covering four languages, because renaming would break published URLs.
- Key statistical concepts are introduced inside `::: {.callout-important}` fenced divs — reuse that pattern for new definitions.
- Chapter titles/headers use `.unnumbered` (`{.unnumbered}` / `{-}`) for front-matter-style sections; numbered chapters omit it.

## Git

Default branch is `main`; `repo-url` in `_quarto.yml` points at `https://github.com/pem725/GradStats-Book`. `.gitignore` excludes `.quarto/`, RStudio session files, `_publish.yml`, and `/_book/` — so rendered output is **not** tracked and a local render never dirties the tree. Publishing is handled by `.github/workflows/publish.yml`, which renders on every push to `main` and deploys to the `gh-pages` branch; that workflow's package list must be kept in sync with what the chapters actually load.
