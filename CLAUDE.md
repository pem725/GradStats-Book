# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **Quarto book** — an open, freely-editable graduate statistics textbook for the social and behavioral sciences (working title in `_quarto.yml`: "Statistics by Us for You"). The "source" is a set of `.qmd` (Quarto Markdown) chapter files that interleave English prose with executable code chunks in **R, SPSS, Julia and Python**. There is no application to run and no test suite; the deliverable is the rendered HTML book in `_book/`, published at <https://pem725.github.io/GradStats-Book/>.

Licensed CC BY-NC-ND 4.0. Authored by Patrick E. McKnight, Simone C. McKnight, Jeffrey Stuewig, and Todd B. Kashdan (author list in `_quarto.yml`).

## Build & preview

```sh
quarto preview      # live-reloading local server; use this while editing
quarto render       # full build of the whole book into _book/
quarto render 02-distributions.qmd   # render a single chapter (faster feedback)
```

Rendering **executes every code chunk in all four languages** — R, SPSS (via PSPP), Julia and Python. A chapter can therefore break the build through a runtime error in any of them, not just a Markdown mistake. When a render fails, read the interpreter's error in Quarto's output.

Requires: `quarto` (1.6.x) and `R` with `knitr`, `tidyverse`, `broom`, `plotly`, `png`, `magick`. The other three are optional locally — see "The four-language build" below for what a missing one does. A full render takes 35–45 minutes because four interpreters run during it; use `quarto render <chapter>.qmd` for feedback while editing.

## Structure

- **Chapter order and book metadata live in `_quarto.yml`** (`book.chapters`), NOT in filename order. A new `.qmd` file is invisible to the book until it is added to that list. Filename numbers reflect the order chapters were *written*, not where they sit — 31 comes before 12, 18 before 31. Never infer position from a filename; read `_quarto.yml`.
- Twelve `part:` sections, in book order: The Basics · Making Inferences with Data · Checking Our Data · Preparing Our Data · Using Models · Latent Variable Models · Causal Inference · Beyond the Normal Curve · Displaying Data · Statistics in the Wild · The Methods in Practice · Appendices.
- Front matter: `index.qmd` (welcome/license), `foreword.qmd`, `preface.qmd`, `author.qmd`, `intro.qmd`. Numbered files `02-`…`33-` are the body chapters; the appendices are `three-languages.qmd`, `setup.qmd`, `required-packages.qmd`, `changelog.qmd`; `references.qmd` closes the book.
- `_book/` is generated output — do not hand-edit; it is regenerated by `quarto render`.
- `img/` holds figures (e.g. the cover `img/MRES2wbg.png`). `data/` holds datasets and their per-language loaders; `setup/` holds the shared `load_data.{R,sps,jl,py}`.
- `STATUS.md` is the working dashboard — current counts, open items, and the lessons each broken build taught. Read it for state; keep it updated.

## The four-language build

`_engines.R` (sourced by `_common.R`, so any chapter that sources that gets it) defines knitr engines for `pspp`, `julia` and `python`. Each writes the chunk to a scratch file, shells out to the real interpreter, captures stdout, and collects any figure the chunk drew.

- **No state crosses chunks.** Each runs in a fresh process, so every non-R tab loads its own data. Shared loaders live in `setup/load_data.{R,sps,jl,py}`, per-dataset ones in `data/` (`knox.sps`, `mod3data.sps`). When a tab depends on a bespoke R helper defined earlier in the chapter, it stays static rather than faking it.
- **A missing interpreter degrades to static text** and logs `BOOK-STATIC [engine] chapter label: why`. The build never fails just because a machine lacks PSPP, Julia or Python — grep a render log for `BOOK-STATIC` to see which tabs quietly showed less than they promised.
- **SPSS runs under PSPP, which is a subset.** No `UNIANOVA /CONTRAST` — spell codes out with `COMPUTE` and feed `REGRESSION`. No `FACTOR /EXTRACTION=ML` — use PAF and note the one-word change for real SPSS. Use `GLM`, not `UNIANOVA`. Factor signs are arbitrary and PSPP sometimes flips one. `/DELIMITERS` reads escapes **literally**, so `' \t'` means a backslash and a letter, not a tab — and it fails silently by sliding values into the wrong variables.
- **`LD_LIBRARY_PATH` must be cleared before launching a child.** R exports it pointing at its own lib directory; inherited, it makes Python's compiled extensions resolve against R's BLAS/LAPACK and `import pandas` dies — while the same command works fine from a shell. `.book_run()` handles this; do not bypass it.
- **CI installs all four toolchains** in `.github/workflows/publish.yml`: pspp, poppler-utils and libmagick++ (PSPP charts go through `pdftoppm` and `magick`), Julia pinned to 1.11.5 with the committed `Manifest.toml` instantiated, Python 3.12 in `.venv` from `requirements.txt`. A "Verify the toolchains" step runs the engines' own probes before the render and fails the job if Julia or Python is unusable. Keep that step and the package lists in step with what the chapters actually load.
- **One figure geometry for all four languages** — 7 × 4.5 in at `fig-dpi: 96` (Quarto doubles it), set in `_quarto.yml` and read back by `_engines.R`, so a reader flipping between tabs sees the same picture at the same size.
- **The reader's data comes from the book's own site, not GitHub.** `setup/make_data_zip.R` runs as a `post-render` hook (declared in `_quarto.yml`) and builds `_book/gradstats-data.zip` — `data/`, the four `load_data.*` loaders, and a plain-language `README.txt` — which `setup.qmd` links as `gradstats-data.zip`. It must be **post**-render: Quarto empties the output directory when a render starts. Never commit the zip; it is built every time so it cannot drift from `data/`. It needs the `zip` binary, which the workflow installs; without it the hook logs `BOOK-NOZIP` and lets the build finish rather than failing. Assume readers do not use git — co-author Jeff teaches SPSS and does not — so anything they need must be reachable by clicking one ordinary link.

## Conventions & current state

- **Every chapter is drafted and renders clean.** No stubs, no `foo`/`bar`/`baz` placeholders. Two blanks are deliberate: `foreword.qmd` is held for an invited outside colleague, and the `RELIABILITY /MODEL=ALPHA` section of `10-reliability.qmd` is reserved for co-author Jeff Stuewig. Do not fill either in unless asked.
- **Voice matters.** The prose is informal, personal, warm, and *supportive* — an encouraging teacher, not a stand-up act. First-person asides marked `(PEM)` are welcome. **Avoid sarcasm, innuendo, and forced cleverness, and avoid AI-writing tics** (em-dash pile-ups, rule-of-three flourishes, breathless hype, rhetorical-question spam, "it's not just X, it's Y"). Write plainly and clearly, the way McKnight and Kashdan actually write. When in doubt, cut the joke and keep the point.
- **POMP is the house standardization.** Percent Of Maximum Possible — `100 * (x - min) / (max - min)` — puts differently-scaled measures on a common 0–100 scale. Introduced in `06-zdistribution.qmd`; prefer it when comparing across measures.
- R chunks are teaching artifacts: keep them short, self-contained, and heavily commented so a student can read them top to bottom.
- **The running code is tidyverse throughout.** Each chapter opens its first chunk with `library(tidyverse)` (plus `library(broom)` where models appear) and `source("_common.R")`. Use `tibble`/`dplyr` over `data.frame`/`$`-indexing, `purrr::map_*` over `sapply`/`replicate`, `readr::read_csv` over `read.csv`, and `ggplot2` for every figure; `plotly` is used for interactive 3D (the learning-helix in `intro.qmd`). The *statistical engines* stay base R — `lm`, `aov`, `glm`, `factanal`, `prcomp` — as do from-scratch teaching derivations; `broom` (`tidy`/`glance`/`augment`) turns their output into printable tables.
- **Numbers print to two decimal places**, via `round2()` from `_common.R`; models go through `tidy2()`. P-values are the exception — `fmt_p()` gives three decimals with a `< .001` floor, because a p-value shown as `0.00` misteaches. `22-tables.qmd` deliberately overrides this, since that chapter is about choosing digits on purpose. `_common.R` is reprinted in full in `required-packages.qmd`, so add any new helper there too.
- Sequential algorithms (EM in `29-latentclass.qmd`, JMLE in `18-rasch.qmd`) keep their outer `for` loop — each sweep depends on the last — with a comment saying so; only the genuinely independent inner sweeps use `map_*`.
- **Every executable chunk is wrapped in a four-language `::: {.panel-tabset}`**, headers in this order: `### R` / `### SPSS` / `### Julia` / `### Python`. **All four tabs execute** — `{r}`, `{pspp}`, `{julia}`, `{python}`, each in braces. A fence without braces (```` ```julia ````) is highlight-only and does NOT run; that one-character difference is the whole distinction between a verified result and one the reader has to take on faith. When a language genuinely lacks the procedure, its tab says so plainly and names the tool that does it — never invent syntax that would not run. The `three-languages.qmd` appendix keeps its filename despite covering four languages, because renaming would break published URLs.
- **Include/exclude rule for tabs.** Wrap a chunk only when it runs a standard, reproducible procedure with a faithful one-command equivalent elsewhere (descriptives, correlation, t-test, ANOVA, regression, logistic, chi-square, PCA/EFA, categorical coding). Leave R-only: plotting, in-chunk simulation and setup, and static tool demos of packages that are shown but not executed. Do not manufacture an equivalent for bespoke code — that misteaches. A from-scratch teaching derivation (bootstrap, JMLE, EM, grid Bayes, hand-computed alpha) *may* carry other languages when the arithmetic translates honestly and the translation reinforces that the statistics do not depend on the software — `10-reliability.qmd` and `24-casestudy-depression.qmd` both do this. What it must not do is fake a one-command equivalent that does not exist.
- **A tab that needs a helper must define it.** Nothing carries between chunks in the non-R languages, so a downstream tab repeats the loader and the helper rather than referring back. That repetition is the honest cost of every tab being runnable on its own; do not "fix" it by hiding the helper in a setup file when the chapter's point is to show the derivation.
- **Callouts are rationed, and the ration is roughly one per major section.** A `::: {.callout-important}` marks the single thing a reader must not miss; stacking several in a row trains people to skip all of them, which is how `intro.qmd` ended up with nine consecutive boxes nobody read. **Never place callouts back to back.** Related definitions belong in running prose with **bold** terms, plus a compact summary table for lookup — that is the pattern the introduction now uses. Before adding a callout, check what the surrounding section already has.
- Long optional detail goes in a collapsed `<details>`/`<summary>` block rather than a callout, so the page stays skimmable and the reader opts in (see "What To Expect" in `intro.qmd`).
- Chapter titles/headers use `.unnumbered` (`{.unnumbered}` / `{-}`) for front-matter-style sections; numbered chapters omit it.

## Git

Default branch is `main`; `repo-url` in `_quarto.yml` points at `https://github.com/pem725/GradStats-Book`. `.gitignore` excludes `.quarto/`, RStudio session files, `_publish.yml`, and `/_book/` — so rendered output is **not** tracked and a local render never dirties the tree. Publishing is handled by `.github/workflows/publish.yml`, which renders on every push to `main` and deploys to the `gh-pages` branch; that workflow's package list must be kept in sync with what the chapters actually load.
